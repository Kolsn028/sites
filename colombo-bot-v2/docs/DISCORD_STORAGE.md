# Логи, копии и отпуск

Два канала в категории управления: «логи-бота» и «данные-бота».
Их видят High, Deputy Leader, Leader и владелец/администраторы Discord.
Рекрутам доступ не выдаётся. Переименование существующей Ass.Deputy в High
не меняет её ID; сохранённая привязка используется первой.

Копия содержит настройки, анкеты и решения, статистику рекрутов, дела,
отчёты, контракты, отпуска, МП, основной/резервный состав и подтверждения.
Каждый сервер получает только свои строки. Токены не включаются.
Скриншоты остаются в исходных сообщениях Discord; копия сохраняет ссылки,
а не сами изображения. Удаление исходных сообщений может лишить их доступности.

После изменения базы запись ставится в очередь. Последовательные изменения
объединяются в течение 3 секунд; ошибки повторяются по таймеру до 60 секунд.
При недоступном Discord несохранённые изменения остаются только локально.
Поэтому перед деплоем High или старшие выполняют /backup_now и ждут
подтверждения. На время первого переноса приостановите обработку заявок.
Нет гарантии нулевой потери данных между последним подтверждённым сохранением
и внезапным завершением процесса.

## Первый перенос — ДО деплоя

Старая версия ещё не отправляет копии. Не перезапускайте её до переноса:
монтирование пустого диска сейчас не сохранит содержимое старого контейнера.

Внутри работающего контейнера, в /app, запустите
scripts/seed_discord_backup.py из этой ветки. Скрипт читает SQLite в
согласованной read-only транзакции, создаёт закрытый канал данных, отправляет
копию и скачивает её обратно для проверки SHA-256. Значение DISCORD_TOKEN
используется локально и не выводится.

Скрипт напечатает DISCORD_BACKUP_CHANNEL_IDS с JSON-сопоставлением
серверов и каналов. Сохраните это значение в Railway Variables одновременно
с установкой обновления. На время между копированием и деплоем не проводите
решения/изменения: они иначе останутся в старом контейнере.

После запуска должны появиться «Discord backup restored» в логах Railway.
Затем бот создаст «логи-бота». /setup повторно не требуется, когда исходная
копия содержала правильные привязки. /backup_now подтверждает новую копию.

Без переменной бот ищет каналы по технической метке, без учёта имени.
С переменной дополнительно обнаруживает удаление ожидаемого канала и
останавливает запуск вместо создания пустых данных. Дубли каналов, ошибки
целостности и конфликты ID также не замалчиваются. Читается последняя
корректная копия среди 50 последних сообщений канала. Старые копии не удаляются.
Лимит одной копии: 64 МБ JSON и 8 МБ сжатого файла.

## Отпуск

Новые отпуска добавляют только «Отдых». Возврат снимает только роль,
сохранённую при одобрении, даже если её привязка позднее изменилась.
Остальные роли сохраняются. Для старых отпусков со снимком сохранён возврат
ранее снятых ролей; отсутствующий снимок не подменяется догадками.
