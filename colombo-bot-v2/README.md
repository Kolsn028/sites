# Colombo Family Bot v2

Discord-бот на Python / discord.py для управления заявками, рекрутерами, личными делами, активностью и отпусками.

## Возможности

- заявки через красивую панель и Discord Modal;
- приватная ветка заявки с кандидатом и рекрутерами;
- меню рекрутера: принять / отказать / отложить / вызвать на обзвон;
- автоматическая статистика и лидерборд рекрутеров;
- автоматическая выдача роли принятого участника;
- автоматическое создание личного дела после принятия;
- приватное личное дело участника;
- загрузка скринов/видео активности;
- типы активности: Капт, МП, МШ, тренировка, другое;
- подтверждение или отклонение активности High Staff;
- `/profile`, `/activity_top`, `/inactive`;
- автоматический контроль неактива;
- отпуск/отдых с обработкой Assistant GP Leader / Dep Leader;
- исключение отпускников из контроля неактива;
- SQLite с WAL, индексами и кэшем конфигурации;
- persistent Discord Views после рестарта;
- Dockerfile и health endpoint `/health`.

## Запуск

1. Создайте Discord Bot в Developer Portal.
2. Включите `Server Members Intent` и `Message Content Intent`.
3. Скопируйте `.env.example` в `.env`.
4. Укажите `DISCORD_TOKEN` и `GUILD_ID`.
5. Установите зависимости: `pip install -r requirements.txt`.
6. Запустите: `python main.py`.
7. На сервере выполните `/setup`.
8. Отправьте панели `/panel_application`, `/panel_vacation`, `/panel_case`.

## Northflank

Для сборки используйте Dockerfile из каталога `colombo-bot-v2`. В переменные окружения добавьте `DISCORD_TOKEN` и `GUILD_ID`.

Важно: текущая версия хранит данные в SQLite. Для долгой облачной эксплуатации лучше подключить persistent volume либо перейти на PostgreSQL.

## Безопасность

Никогда не коммитьте `.env` и токен Discord в GitHub. `.env` уже добавлен в `.gitignore`.



## Обновление: автоматическая структура и приватные ветки

В Discord администратор или настроенный Leader запускает `/setup` (алиас `/setup_auto`).
Параметры ролей: `leader`, `deputy`, `ass_deputy`, `recruit`, `novizio`, `colombo`, `vacation`.
Без параметров используются сохранённые назначения, а при первом переходе на эту версию —
точные уникальные имена ниже. Если роль отсутствует, создаётся новая без серверных разрешений;
новые должностные роли нужно вручную выдать сотрудникам. Повторяющиеся имена требуют явного выбора.

| Роль | Поведение |
| --- | --- |
| Leader (красный) | Полное управление ботом, заявки, отчёты, отдых. Не упоминается в уведомлениях. |
| Deputy Leader (синий) | Заявки, просмотр личных дел, отдых. Проверка отчётов запрещена, даже с Administrator или Ass.Deputy. |
| Ass.Deputy | Заявки, личные дела, проверка отчётов и отдых. |
| Recruit- | Просмотр и обработка заявок. Получает уведомления о новой заявке и принятии. |
| -Novizio- | Выдаётся после принятия заявки; открывает функции состава. |
| Colombo | Выдаётся вошедшим людям и существующим участникам при /setup; не открывает служебные разделы. |

Заявку видит кандидат в своей приватной ветке и Recruit-, Ass.Deputy, Deputy Leader, Leader.
Числовая позиция посторонней роли сама по себе не даёт доступа к функциям бота.
Серверные администраторы Discord всегда могут просматривать каналы; ограничения просмотра
не могут отменить системное право Administrator. Владелец сервера имеет полномочия Leader.
Для исключения случайных пингов руководства уведомления направляются конкретным рекрутерам,
исключая носителей Leader/Deputy Leader, даже если у них есть Recruit-.
По умолчанию все прочие упоминания подавлены. Приём не завершается, если бот не смог выдать -Novizio-.

Команда создаёт категории набора, состава, управления и личных дел; каналы подачи заявок,
веток рекрутеров, обзвона, отдыха, статуса отдыха, журналов и рейтинга; три панели с кнопками.
Повторный запуск использует сохранённые ID и обновляет панели. Существующие вручную
настроенные каналы не удаляются и их права автоматически не изменяются.
Каналы с меткой Colombo в topic получают обновлённые разрешения при смене ролей.

Права бота: Manage Channels, Manage Roles, Create Private Threads, Manage Threads,
Send Messages, Send Messages in Threads, Embed Links, Read Message History, View Channels.
Роль бота должна находиться выше ролей семьи и отдыха. Server Members Intent и
Message Content Intent должны быть включены в Discord Developer Portal.

Заявки рекрутам и на отдых создают отдельные приватные ветки. Участнику нужен просмотр
родительского канала; приглашение в ветку не отменяет это требование Discord.
Администраторы и сотрудники с Manage Threads могут видеть приватные ветки.
Решение по отдыху закрывает ветку. Для старых заявок отдыха в обычном канале кнопки сохраняются.

### Оформление

Единый стиль карточек: бордовый акцент набора, золотой акцент отдыха, серо-синий акцент
личного дела, короткие пошаговые блоки, подпись Colombo и время обновления.
Панель заявки короткая, с оригинальным баннером `assets/colombo-banner.png` как вложением Discord.
Остальные панели используют аватар бота; `BANNER_URL` задаёт им внешний баннер. `FAMILY_NAME`, `FOOTER_TEXT` и `EMBED_COLOR` настраивают бренд.
Discord задаёт фон интерфейса и доступные цвета кнопок.

### Данные на Railway

Подключи постоянный Volume к `/app/data`. По умолчанию база находится в `data/bot.db`
при рабочем каталоге `/app`; можно явно задать `DATABASE_PATH=/app/data/bot.db`.
Пустой том НЕ переносит данные старого контейнера. Перед первым подключением диска
нужна согласованная резервная копия SQLite через Connection.backup() и восстановление
в том, либо явное согласие владельца начать с пустой базы. Не публикуй базу в GitHub.
При последующих запусках схема обновляется без удаления таблиц и записей.

Проверка: `python -m unittest discover -s tests -v`.
